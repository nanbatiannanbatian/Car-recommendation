# 用车条件因素库（跨能源比较的前置条件）

> 用途：B 类「跨能源打分榜 + 环境分」在比较燃油/油混/插混/增程/纯电之前，先把用户的用车条件问清楚、量化成可执行的加减分与硬条件。
> 单一事实源：`modules/envscore/engine.py`（11 项因素 + 7 条硬条件 + TCO）；浏览器镜像 `engine.js` 由 `env_equivalence_regress` 等价回归守护。
> 本文件只记录「为什么是这项、量化依据是什么、落到哪条规则、为什么删掉了那些」，不重复代码里的权重数字。
> 最近更新：2026-11-24（v10.55.0，因素 20→13，删 7 项并留档理由）。

## 一、设计原则

1. **先定形式，再选车**。同一价位里五种能源混在一起时，先回答「你的条件更适配哪种能源形式」（`engine.recommend_form`），再看形式内的具体车型；否则 12-14 万里一台纯电和一台插混的 0.3 分差会被误读成「谁更好」。
2. **纯电优先，但有条件**。无硬条件冲突的纯电 +0.5（用户明确「可以纯电尽量纯电」）；无固定充电、极寒、高频长途、短持有等条件在对应项扣分或触发硬条件——「尽量纯电」≠「无条件纯电」。
3. **能物理算的就物理算**。续航用 `ev_range_model` 的物理模型（电耗 × 工况 × 温度 × 暖风 × 电压平台），不用 CLTC 拍脑袋打折。
4. **画像必须先自洽**。互相矛盾的条件（营运 + 8 年持有、纯电 + 无桩 + 极寒 + 高频长途）先提示（`engine.check_profile`），再谈排名。
5. **事实不进分**。TCO、保值率、销量只做披露列，不进产品力分。
6. **问一项就得换一个结论，否则别问**（v10.55.0 新增判据）。每项条件都要能用「改了它，结论真的变吗」来辩护：只造成 ≤2 分同向微调、或只改展示数字不改排序的项，一律删掉，不占用户回答成本。

## 三、7 条硬条件（全额计入 + 降档 + 红标）

| 编号 | 触发 | 分值 | 逻辑 |
|---|---|---|---|
| H1 | 纯电 + 完全没有固定充电（且单位不可充） | −15 | 补能不可持续，不是「多花时间」而是「不可用」 |
| H2 | 纯电 + 极寒（≤-20℃）+ 车价≤15 万 | −12 | 低价纯电多为小电池 + 无热泵，冬季可用续航腰斩 |
| H3 | 纯电 + 持有 <3 年 | −8 | 3 年残值最低的组合，折旧吃掉能源节省 |
| H4 | 纯电 + 单次 >500km 且有效续航不足 | −10 | 单程需两次以上补能，节假日不可行 |
| H5 | 燃油/油混 + 限牌城市 | −8 | 牌照成本/通行限制是硬门槛 |
| H6 | 燃油/油混 + 营运 | −10 | 每公里能源成本劣势在城市高频场景被放大 |
| H7 | 插混/增程 + 北京/上海 | −8 | 京沪不享受纯电式绿牌红利，形式优势被抹平 |

## 四、画像自检规则（`engine.check_profile`）

- 营运 + 单次 >500/高频长途、营运 + 8 年持有、营运 + 家庭第二辆 → 告警（条件相互矛盾）。
- 无固定充电 + 低温 + 高频长途 → 告警「纯电基本无解」，建议直接看插混/油混/燃油。
- 低里程 + 无桩、短持有 + 无桩 → 提示「纯电经济性不成立」。
- 增购第二辆 + 长途高频 → 提示「长途交给油车，纯电按日常里程选电池」。
- 高里程 + 几乎全短途 → 提示「典型城配/网约特征，纯电最合适」。

## 五、已删条件与删除依据

删前用 45 款紧凑级跨能源榜做逐项扰动实测：对每项条件遍历所有非默认选项，记录「触发硬条件的车数 / 综合分变化的车数 / 单项最大 Δ / 前十交集 / 形式结论是否翻转」。

| 条件 | 实测影响 | 删除理由 |
|---|---|---|
| 夏季最高气温 | 0 台触发硬条件、14 台变化、最大 Δ1.0、前十全保留 | 只影响续航乘子 ±1 分，且与冬季温度判据同源，问一遍就够 |
| 驾驶风格 | 7 台变化、最大 Δ2.0、前十全保留 | 主观项，用户自评方差大于模型影响，形同噪声 |
| 空调使用 | 7 台变化、最大 Δ2.0、前十全保留 | 同上；暖风/制冷已按季节基线固定在物理模型里 |
| 停放环境（露天） | 14 台变化、最大 Δ2.5、前十全保留 | 与冬季气候带高度重合（露天=夜间更冷），重复计分 |
| 驻车用电（等人/午休） | 45 台全变化但最大 Δ1.0、前十全保留 | 典型场景覆盖面窄（≤1 分），只多一段解释成本 |
| 露营外放电 | 45 台变化但最大 Δ0.5、前十全保留 | 影响最小，属配置偏好而非用车条件 |
| 家充电价档 | 0 台综合分变化（只改 TCO 展示） | 不进分数，且谷电/居民/商用三档把形式结论带偏的风险大于收益；现统一按谷电 0.35 元/度口径并在页面标注 |

**v10.56.0 再删 2 项**（同一判据，用户逐项提审后执行）：

| 条件 | 实测影响 | 删除理由 |
|---|---|---|
| 地形/路况 | 45 台变化、最大 Δ2.3、前十全保留、无硬条件 | 路线级平均（丘陵+10~20%、高山+25~40%）拿去近似一条具体路线必然偏，用户也难自评准确；改用方法区提示「山区/高原自行上浮电耗 10~25%」，不假装能算准 |
| 方盒子造型 | 2 台变化、最大 Δ2.0、前十全保留 | 本质是车型属性（风阻/车身形式），让用户替车型回答风阻问题等于把客观参数变主观勾选；改由车型自身 Cd/CdA 承担，并在「车身形式」筛选区分轿车/SUV/MPV/越野车/方盒子SUV |

保留 11 项的统一理由：都带硬条件（H1-H7）、或能把能源形式结论翻面（无桩 / 极寒 / 高频长途 / 短持有 / 限牌 / 营运 / 增购第二辆）。

**限牌城市为何不删**（用户提出删，评估后保留）：它是 7 条硬条件里唯一判「这种车在当地能不能用」的项——H5 燃油/油混 −8、H7 京沪插混/增程 −8；实测触发 33 台硬条件、单项最大 Δ8.0。删掉会让限牌城市用户看到油车进前十，属结论级错误。

## 七、已知边界

1. 地形不再是模型项：山区/高原请自行把电耗上浮 10~25%（丘陵取下沿、高山取上沿），页面不做路线级估算。
2. 增程高原衰减与具体增程器（涡轮/自吸、发电功率）强相关，代码用统一 −0.6，配置级差异留给逐配置页。
3. TCO 家充固定谷电 0.35 元/度（电价档条件已移除），实际电价差异用页面说明提示，不进分数。
4. 所有因素默认值 = 人群常见画像（家庭唯一用车、平原、有家充、谷电、非营运），页面对默认值有明示。
5. 被删的 9 项仍保留常量（`AC_LEVEL` / `DRIVE_MULT` / `TERRAIN_MULT` / `TCO["elec_home_by"]` 等）以兼容旧调用，但不再被任何条件驱动；`adjust/range_calc/verdicts/tco` 遇到这些旧键会安全忽略（selftest 有断言）。
6. 车身形式（轿车/SUV/MPV/越野车/方盒子SUV）是**车型字段**而非条件：`body_label()` 只做官方车身类型映射；越野车需 `offroad`/非承载标记、方盒子SUV 需 `boxy` 标记，拿不到就停在「SUV」，不靠外形主观猜。筛选器选项从池内实际取值派生——池里没有 MPV/越野车，页面上就不会出现这两个选项（当前紧凑轿车榜只有轿车）。



## 八、为什么「冬季气候带」用四档，而不是「东北 / 北方除东北 / 南方」三分

用户提出的三分法更贴近日常说法，但会丢两个判据：

1. **丢掉极寒阈值**。H2（≤-20℃ + 车价≤15万纯电 −12）是按「≤-20℃」触发的；三分法里「东北」整片进入该档，沈阳(-22℃)、大连(-15℃) 被同样重罚，而「北方」里的北京(-12℃)、西安(-8℃) 又挤在同一档，无法区分 0~-10 与 -10~-20 两档的续航系数（×1.05 vs ×1.12）。
2. **南方内部跨 0℃**。广州(5℃)、上海(-3℃) 同归「南方」，长三角的冬季衰减被抹成 0，与实测（-10℃ 平均衰减 32.7%）不符。

四档的切分点全部落在有物理含义的温度阈值上，同时给每个档位配上代表城市，用户按「我在哪个城市」即可对号入座：

| 档位 | 温度含义 | 代表城市 | 续航温度系数 |
|---|---|---|---|
| 南方（冬季极少≤0℃） | >0℃ | 广州/深圳/福州/南宁/厦门/海口 | ×1.00 |
| 江淮 / 长江流域 | 0~-10℃ | 上海/杭州/南京/武汉/成都/重庆/长沙 | ×1.05（默认） |
| 华北 / 黄淮 | -10~-20℃ | 北京/天津/石家庄/济南/郑州/西安/太原 | ×1.12 |
| 东北 / 内蒙 / 新疆北部 | ≤-20℃ | 哈尔滨/长春/沈阳/呼和浩特/乌鲁木齐/拉萨 | ×1.20 |

边界说明：辽东半岛沿海（大连约-15℃）在「东北」档会被略重罚，故 hint 明确写「按华北档更接近」；反之亦然。档位键（above0 / m10to0 / m20tom10 / underm20）与温度系数、硬条件判定全部不变，所以这是**纯标签层改动**，历史结论与回归口径不受影响。

## 九、为什么形式结论按「3 个家族」而不是 5 种能源（v10.57.0）

用户原话：「油混合油车如果差别不大，是不是可以合并，就当燃油车了，现在业内、大众好像也没有把两者强行区分」。判断：**合并的是「形式适配结论」的粒度，不是打分与标签。**

合并的依据（全部可复算）：
1. 政策/牌照/税费口径上 HEV 与 ICE 完全同待遇——不进新能源目录、无绿牌、购置税 10%，H5 限牌 −8、H6 营运 −10 同罚；
2. 11 项用车条件里 **9 项两者同分**，只有两处差 1.0 分（年里程 >2.5 万：燃油 −1 / 油混 0；增购第二辆：燃油 −1.0 / 油混 0）；
3. 所以把油混单列成「一种独立能源形式」，会让「形式均分第一名 = 油混」的结论像是在说「油混是一种新品类」，而它实际是燃油家族里更省油的子类。

不合并的部分（必须保留，否则结论会失真）：
1. **逐车标签仍是 油混/燃油**，打分按各自事实算——产品力 9 对同车系实测有 +2.4~+9.4 的差（也有雷凌 −3.2、轩逸 −2.4 的反例），TCO 里油耗与残值（HEV 50% vs ICE 46.07%）不同；
2. 家族内部明细 `members` 单列披露（油混均分 73.0（9 款）、燃油 68.7（22 款）），页面「其中」列展示，合并不掩盖事实；
3. 两处 1 分软调节保留——它们表达的是「高里程时油混真的更省油、增购时燃油真的更冗余」，属事实差异，不是给油混的补贴。

口径变化（必须记住）：45 款池默认画像下，家族均分为 **纯电 72.7（12 款）/ 燃油（含油混）70.0（31 款）**，形式结论首位从「油混」变为「纯电」。这是合并带来的唯一结论级变化，且更接近真实取舍（默认画像有家充、无长途、不限牌）。
