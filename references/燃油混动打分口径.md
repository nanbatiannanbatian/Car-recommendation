# 燃油 / 油混 / 插混 8 维打分口径（v10.54）

跨能源形式混排时，纯电有「三电池 + 7 维」，燃油/油混/插混必须有同等刻度的分数，否则榜单只能按电耗逻辑硬排。
本文件说明这套分**怎么来的、缺什么就不给什么、以后怎么自动重建**。

## 1. 一句话链路

```
compact_sedan_universe.json（只列车名，级别/动力一律由官方字段判定）
   → modules/research/ah_series.py      抓汽车之家车系页 + 参数页，落缓存 runs/_ah_cache/<sid>.json
   → modules/research/build_ice_scores.py  按能源形式分组 → 主力款参数 → 打分
   → modules/engine/param_score.py      8 维绝对锚点插值 + 缺维归一
   → data/gen/ice_scores_compact.json   分数数据集（board 只读它）
   → modules/board/build_compact_sedan.py 与纯电池合并成榜（缺文件/超 7 天自动重跑）
```

命令行：`python3 modules/research/build_ice_scores.py --universe compact_sedan_universe.json`
（`--fill-bev` 专补纯电三电；`--refresh` 强制重抓；`--selftest` 零网络复核）。

## 2. 数据源（只用已验证可用的）

| 用途 | 端点 | 拿到的字段 |
| --- | --- | --- |
| 官方级别/能源类型/口碑/PPH | `https://www.autohome.com.cn/<sid>/` | `levelName`、`energytype`、`kouBeiData.average`+7 维、`cmpSeriesScore`（按 seriesId 认领本车：reliabilityPPH/newCarPPH/样本数） |
| 逐款型参数 | `https://car.autohome.com.cn/config/series/<sid>.html` | `var config` 结构化矩阵，按字段 id 定位（`modules/research/param_fields.py`） |
| 销量 | 懂车帝 `rank_data` 快照 `runs/dcd_sales_snapshot_202611.json` | 车系口径·含所有能源形式 |

**采不到的（不许假装有）**：参数页只有 8 组（基本参数/车身/发动机/电动机/电池充电/变速箱/底盘转向/车轮制动），
**没有安全气囊、L2/NOA、屏幕芯片组**；底盘组对所有能源类型整组为空。易车 `peizhi` 只回桩页。

## 3. 能源类型映射（含变体）

- 官方码：`0/1→ICE，2→HEV，3→PHEV，4→BEV，5→EREV`。
- 文本兜底 `map_energy()`：`汽油/柴油/汽油+CNG/汽油+48V轻混系统→ICE`（48V 是弱混，不算油混）；
  `汽油电驱/超混电驱→HEV`（日产 e-POWER 串联，发动机只发电、不能外接充电）；
  `插电…→PHEV`；`增程…→EREV`；`纯电…→BEV`。
- 纯电不归本管线打分（走三电池 7 维），`build_ice_scores` 会显式 skip 并写进 gaps。

## 4. 打分：8 维、能源中性

权重与跨能源页 `build_energy_compare.DIMS` 完全同值（0.18/0.162/0.135/0.126/0.117/0.100/0.090/0.090），
`param_score_regress` 会断言两边不许漂移。

| 维度 | 输入 | 公式要点 | 证据 |
| --- | --- | --- | --- |
| 动力总成 | 比功率 kW/t、WLTC 油耗/馈电油耗、口碑驾驶 | 锚点插值 40→3.8 … 140→9.6；油耗每档加减；纯电续航（PHEV/EREV）加分 | B |
| 安全 | — | **恒 null**：无官方碰撞判档（`ice_crash.json` 只存“有测评记录”）。留 `facts["crash_grade"]` 钩子，有判档才填 | — |
| 智驾 | 口碑「配置」 | 5.0 +（口碑−4）×2（自样本代理，无实测） | B- |
| 空间 | 轴距、后备厢、口碑空间 | 轴距 2550→4.2 … 2950→8.5；后备厢档位 ±0.3；口碑×1.2 | B |
| 性价比 | 马力/万元、口碑性价比 | 6→2.8 … 26→9.7；口碑×0.8 | B |
| 质量品控 | 可靠性 PPH（主）、新车 PPH（辅） | 9.9 − 0.0135×可靠性PPH − 0.008×新车PPH | A-（PPH 为大样本聚合） |
| 操控 | 零百、口碑驾驶 | 6.5s→9.4 … 16s→4.0；口碑×0.5 | B- |
| 车机座舱 | 口碑「内饰」 | 5.0 +（口碑−4）×2 | C+ |

缺维规则：`MIN_DIMS=5`，不足 5 维返回 None（证据不足，不入榜）；≥7 维记证据 B，否则 C。
**任何维缺失就不参与加权、也不填假分**——所以不要拿「安全」去横向比，各车安全分都是空的。

## 5. 主力款配对（最容易算错的地方）

打分必须用**同一台车**的参数：功率 / 车重 / 价格都取「价格中位那台款型」（`group["main"]`）。
历史 bug：用「全系最大功率 ÷ 丐版指导价」会得出 29 马力/万元 → 性价比恒满 10 分，头部全是国产 1.5T。
现在 `price_ref` 与 `system_kw` 都来自主力款，`param_score_regress::t_main_trim_pairing` 守这条。

## 6. 混动系统功率估算（明标为估算）

官方「系统综合功率」不公开，按架构保守估：

- **串联**（发动机只发电：e-POWER、增程）→ 取电机功率 `max(engine, motor)`（判据：`engine_kw < 0.6×motor_kw`）；
- **并联/混联**（发动机可直驱）→ `engine_kw + 0.5×motor_kw`（保守，故意不取满额叠加）。

因此 HEV/PHEV 的动力分是「可解释的估算」，不是厂商口径；页面与 explain 里都保留输入值。

## 7. 缓存与自动重建

- 缓存：`runs/_ah_cache/<sid>.json`，TTL 30 天，串行 0.8s 抓取，失败记 `fetch_error` 不抛。
  缓存 JSON 会把 int 键变 str，读回统一 `_coerce` 成 int，并用 specs 重算 aggregate（改口径不必重抓）。
- 榜单侧：`build_compact_sedan.py` 发现 `data/gen/ice_scores_compact.json` 缺失或超 7 天 → 自动重跑采集+打分；
  纯电候选缺三电 → 自动 `fill_bev` 从参数页补电池/CLTC，补不到才进「未入榜·待补采」。
  **扩车型只改 universe JSON，不用改代码、也不用再问用户。**

## 8. 已知边界

1. 无官方碰撞判档 → 安全维空缺，跨形式比较时实际只有 7 维在参与加权。
2. 智驾/座舱是口碑代理（B-/C+），不能当配置表硬证据引用。
3. 销量为车系口径·含所有能源形式，不能与「纯电分动力销量」直接对齐。
4. 掀背车（凌渡、UNI-V）按轿车收；方盒子风味越野轿车段不涉及（由 `box` 条件在环境分里处理）。
5. 速腾 HEV 无指导价 → 该组跳过并写进 gaps，不猜价。

## TCO 油耗口径（v10.58.0）

油混的油耗优势必须取**该动力形式自己的款型**，不能整条车系共用一批：h_series.spec_power() 按参数页「能源类型」判定，缺失才用款型名关键词（双擎/混动/电驱→油混、插电混动→插混、增程→增程、纯电→纯电），拿不到记 unknown 不猜；拆不出该动力则退回全车系并在产出里标 	rims_src=series_all 披露。实测卡罗拉油混 4.13L vs 燃油 5.88L、轩逸 4.13 vs 5.94、星瑞 4.10 vs 6.20。回归 power_split_regress.py。
