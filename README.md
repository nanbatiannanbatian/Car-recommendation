# Car recommendation

> 可信购车榜单引擎：口径闸门 / MCDA 稳健性检验 / 8 维打分统一榜 / 总候选池 / 多源交叉核验 / 证据分层 / 历史回测。
> 无模型调用，同一输入必得同一输出。当前版本 **v8.3.3**。

## 这是什么
WorkBuddy 用户级 skill。核心是「车型排行榜全链路」：按需搜榜入池→取数→闸门→8 维打分→稳健性→三档→审查→报告，
外加 工信部备案抓取/上榜预测/第三方视频证据/被动安全配置核验/数据仓库回测。**榜单链路全程无模型调用**，
同一输入必得同一输出。原多模型辩论引擎已于 2026-11 移除——为什么不用 LLM 直接排名，见 SKILL.md《为什么出榜流程不含 LLM/辩论》。

现行榜单口径（v7→v8.3.3）：**打分榜是唯一权威名次来源**——原先单独按 kWh/万元、电耗排的「事实榜」已取消，
降级为打分主榜里标注「参考·不计分」的事实列；所有排行/比较/推荐都从打分榜取名次。
候选池收敛为单一事实源 `master_pool.json`，并支持按提问搜榜摄入、12 源交叉核验。详见下方 v7–v8.3 演进节。

## 被动安全配置为什么不进主分（v5.8）
侧气囊、头部气帘、前排中央（远端）气囊确实重要（NHTSA：侧气帘＋躯干气囊让近侧碰撞死亡率降约 30%）；
但 C-NCAP 2024 版乘员保护已含侧碰、柱碰、侧面远端乘员保护 8 分、保压气帘 3 分——
**气囊是拿分手段，得分率是结果**，再按配置加分等于重复计入。所以本项目：

- 报告出「气囊 侧/帘/中」**事实列**，不计入加权；
- 只对**无官方碰撞成绩**的车给 `scores.safety` 一个受限增量（|Δ| ≤ 0.3，标 low confidence，逐条可撤销）；
- 有成绩的车一律不叠加；「N 气囊」营销口径不映射到布尔字段；
- 未核验的写 `null`，不判劣、不造差异，`airbags.py --todo` 列待补清单。

详见 SKILL.md《被动安全气囊：事实列与受限修正（v5.8 · 方案 A）》及 `airbags.json` 里的 A1–A7 规则。

## 细分维度为什么不进主分（v5.9）

有人提过把轮胎品牌、制动距离、维修经济性、售后态度、保养经济性、底盘用料、试驾感受、
麋鹿成绩、防爆胎、电耗、空间、NVH、智驾、主动安全、流畅度、马力等十几项做成
「成绩好就加一点分，没数据或不确定不加分」。**本项目不做**，理由不是保守，是五个具体失效模式：

1. **缺数据不是随机的（MNAR）**：高曝光、营销预算足的车型披露的参数与实测远多于冷门车型，
   「有数据就加分」实际在给曝光度打分。
2. **选择性披露**：厂商只公布最优条件下好看的数字，缺的往往是不好看的；只加不减会系统性奖励会宣传的品牌。
3. **双重计数**：马力/电耗已在 `powertrain`，空间在 `space`，智驾/主动安全在 `adas+safety`，
   流畅度在 `cabin`，制动/麋鹿在 `control`——再加一次是同一份表现付两次分。
4. **稀疏噪声劫持权重**：覆盖率 10–30% 的维度，方差几乎全由「有没有数据」决定；
   十几个这样的维度叠加，MCDA 会被"谁被报道得多"主导。
5. **不可归一化**：100-0 制动跨媒体的胎温/载重/路面/初速不同；麋鹿只有少数媒体测；
   试驾、售后、NVH、流畅度是主观或口碑口径，样本小且立场不同。

替代方案写成了可执行的 `spec_facts.py` + `categories/spec_facts.json`：

- **16 项决策表**，分六类处置：已吸收·不加分（6）、封顶通道·双向（2）、仅事实列（4）、
  用户偏好滑杆（1）、不采集（2）、有官方口径·待准入（1，中保研 C-IASI 维修经济性指数）。
- **维度级准入门槛 G1–G4**：官方标准化口径 + 覆盖率 ≥70% + 可核验来源 + 加减双向对称。
  不达标就**整条维度禁用**，而不是把缺失记 0 分。本期 3 个待准入维度覆盖率都是 0%，全部禁用。
- **红线 `SCORING_ENABLED=False`**：`apply()` 只写 `c['spec_facts']`，并在返回前对
  `scores/total/adjust` 做前后深比较断言——事实库在代码层面不可能改排名。
- 官网/逐项参数配置照收（按 trim、带 url + quote + 日期），只进事实列与待补清单。

主观项（NVH、试驾）不做成默认权重，交给读者用 `--sliders` 自己拉。

## 安全分对齐（v5.9）

月度链路此前漏了 `sync_cncap.py`，安全分一直是人工值。现已接入并按
`--fill-mode blend`（α=0.5，人工分与中位各半）处理无成绩车：

| 模式 | 中型车 sd | 中型SUV sd | 中大型车 sd | 中大型SUV sd | 说明 |
|---|---|---|---|---|---|
| 原人工分 | 0.348 | 0.379 | 0.368 | 0.442 | 无证据支撑，但保留区分度 |
| `median` | 0.077 | 0.260 | 0.070 | 0.112 | 旧行为：31 款落到同一数，18% 权重失效 |
| `blend`（默认） | 0.208 | 0.276 | 0.210 | 0.414 | 官方成绩覆盖 + 保留相对序，全部标 low |
| `manual` | 0.359 | 0.305 | 0.462 | 0.736 | 只覆盖有成绩车，其余保留人工分 |

三种模式都可回退对照，α 可调。C-NCAP 官网首页最新批次可自动解析，

## 具体配置推荐：为什么列、为什么不加分（v6.0）

榜单只按一个「带内推荐配置」打分，容易掩盖买车时真正要做的选择：
**同一车系不同配置的电池容量、电芯供应商、电压平台可能完全不同。**
例如 MG 07 的 610/650 版是苏州清陶 67kWh 半固态 + 400V/3C，
845 版是宁德时代 91kWh 三元锂 + 800V/5C；腾势 N8 加 1 万多 24.36kWh。

**结论：该列，而且这是很值得补的一层；但不该把它变成加分项。**

1. **层级错位**：榜单回答「买哪款车」，配置推荐回答「这款车买哪个版本」。写进加权分等于用配置性价比替代整车评价。
2. **配置性价比是场景函数**：同一笔 +1 万换大电池，有无家充、南方北方、通勤长途结论相反。
   腾势 N8 这一笔被一篇媒体称「六款中单位成本最划算」，另一篇明确写「只为续航加 1 万没必要」——
   没有唯一正确答案就不能进默认权重。
3. **MNAR 同样存在**：放出逐配置表的是高曝光车型，缺表就吃亏等于给披露完整度打分。
4. **「低配二线电池、高配宁德」的概括不成立**：零跑 C10 逐配置表写的是
   「国轩高科/亿纬动力/中创新航」**同配置多供应商混装**，选配置也规避不了；
   MG 07 是**技术路线分层**（半固态 vs 三元锂 + 400V vs 800V），不是供应商等级。
   电池包由整车厂集成，公开数据不足以按电芯品牌拆分长期可靠性——
   所以本项目**不给供应商排一线/二线/三线，也不映射任何分数**，
   只分类证据形状、只记「是谁、什么路线、上市多久」。

落成 `trims.py` + `categories/trims.json`：

- 按 trim 记录指导价 / 电池容量 / 电芯供应商 / CLTC / 补能 / 电机 / 上市时长，每条带 url + quote + 日期；
- 识别「加价-增配跃迁」：同年款内、每万元 ≥10kWh 或 ≥100km、目标须在价格带内；
  超过 1.5 万加价阈值判 `platform_step`（换整条三电路线），**只陈述事实与场景分支，不给单一建议配置**；
- 建议只从「评分配置」出发，其它支线的加价差异只进事实表；主观取舍按场景分支交还读者；
- 「评分配置」保持候选池原值，不替换、不改 `price_basis`、不动闸门；
- 带外车型（如腾势 N8，26.99–32.99 万）只作算法演示，绝不参与四榜名次。

**红线**：`SCORING_ENABLED=False`，`apply()` 只写 `c['trim_ladder']`，返回前对
`scores/total/adjust/price/trim` 做深比较断言。主报告出精简节，
逐配置表、带外示例与来源链接出 `out/trims.md`；`--no-trims` 可作回测对照。
本期 2026-10 首版核验 4/39 款；**v6.1 已补到 35/39**，见下节。

## v6.2 · 按外部评审做的披露强化（基准名次零变化）

τ(A,D) 0.829–0.868。故正式榜切到 `ice_pool_full.json`，旧 122 款池留作对照。
market 22% vs 24% 交集 9–10/10，**默认权重不动**。

**③ 代价如实披露**：全量池让 space/control/cabin/quality 真实覆盖从 38.5% 降到
**26.7%**、插补比例升到 **73.3%**，`adas` 覆盖率 5.9%。这是「更全候选池」与

## v7.0 · 统一榜单：打分榜唯一主榜，事实榜降级参考列（2026-11-19）

旧链路并行产出「事实榜」（只按 kWh/万元、电耗排序）和「打分榜」，用户混淆「哪个才是排行」。
明确决定：**所有排行、比较、推荐都以打分榜为准**。三条硬规则（固化在 `board_v2.py` + `rank_v2_policy.json`）：

1. **打分榜是唯一权威名次来源**。主榜 = 8 维加权（三电18% / 安全16.2% / 智驾13.5% / 空间12.6% /
   性价比11.7% / 操控9% / 车机9% / **品控10%**），直接复用 `leaderboard.score_rows`，不重写打分逻辑。
2. **事实指标降级为「参考·不计分」列**。kWh、kWh/万元、电耗、CLTC、电芯、800V、月销贴在主榜每行，
   只帮助理解、绝不参与加权。`board_v2.py --selftest` 验证：改某车 kWh 不改变任何名次。
3. **价位差异不设硬排除**。同级别已控制级别混淆变量；价格对竞争力的影响由「性价比」维度吸收——
   贵车性价比分低但产品力仍占优，便宜车反之。「价格相差太多就不排名」会丢掉「多花钱值不值」的信息。

价位段子榜把同一份分数按预算分组（默认 18/28 万切三段），**复用主榜分数、不重新打分**，回答「我这个预算买哪款最好」。

## v8.0 · 总候选池：单一事实源，根治「临时拼池漏车」（2026-11-19）

**踩过的坑**：出「全价位榜」时候选池沿用了围绕 Model Y 竞品采集的 12 款（偏 15–34 万），
漏掉 12–18 万整批高分车——T6 在 12–18 万榜 83.9 第 1，合并前在全价位榜**根本不在候选池**。
不是被打低分，是没进池。

`master_pool.py` + `categories/master_pool.json`（67 款）把散落各 run 的候选池收敛成单一事实源：

- **可检索标签**：级别(cls)/动力(power)/车身(body)/品牌/价格/价位段/证据等级/生命周期；
- **provenance + 配置 SHA256 指纹**，改了逻辑用 `--rescore` 全池重算，不留旧分数；
- 状态标记 `ready / needs_rescore / needs_data`；
- `--audit` 体检覆盖度（防「全价位榜却没低价车」复发）、`--query` 按标签检索子集。

## v8.1 · 按需候选摄入 `--intake`：搜榜→有效销量→入池→复用/待采（2026-11-19）

不挂 automation（用户否决了定时任务，坚持 skill 按需模式）。每次提问先按口径搜懂车帝等销量榜，
复用 `fetch_dcd_sales._trend_pick` 的**有效销量口径**（逐月中位数 + 新车爬坡）筛出该纳入的车：
池里有的直接复用、没有的重新采集。`--intake --dry-run` 可先看清单再 `--apply`。

## v8.2 · 多源交叉核验 `cross_verify`：所有数据源都查、比对、冲突网查确认（2026-11-19）

用户要求「别只查懂车帝一个，要所有数据源都查，最后比对，对不上的网上找资料确认」。
`cross_verify.py` 汇总 12 个已落盘车型级事实源（C-NCAP / C-IASI / 电芯核验表 / 官方级别 / 逐配置表 /
气囊库 / 生命周期 / 口碑 / 第三方实测 / 懂车帝销量 / 基准池 / 总池），按字段级证据等级裁决四态：

- **AGREE** 多源一致；**CONFLICT** 多源分歧（除网查确认外一律列出，绝不静默挑一个当事实）；
- **SINGLE** 单源（标注来源）；**MISSING** 全无。
- 网查确认闭环：冲突 → agent 联网核实 → 写 `verified_overrides.json`（rank100 覆盖）→ 重跑冲突清零。
- **只产出核验表、不进打分链**：`scores/adjust/total` 零改动。量纲隔离（C-NCAP 得分率% ≠ safety 十分制）。

实测总池 67 款：19 个剩余冲突全部是已解释的口径差（16 价格配置价 vs 车系价、3 销量中位 vs 当期），
电芯真冲突经网查清零。

## v8.3 · 分段汇总总榜：无价位段则分段、各段取前几、汇总成总榜（2026-11-19）

用户规则：**「排行榜如果没有价位段，就分几个价位段，每个价位段按前几排名，最后把这几个榜单汇总成总榜」**。
`board_v2.py` 的 `segmented_summary()`：按价位段分组 → 每段取分数前 N（`--per-band`，默认 10；段内不足 10 款按实际款数，如高端段常只有 1–2 款）
→ 汇总后按主榜分数降序成一张总榜。分数全部来自主榜、不重新打分。

价值：保证每个价位段都有车进总榜，避免高端车凭产品力垄断前列。三种视图互补——
全价位主榜回答「综合产品力谁最强」、价位段子榜回答「我这个预算买哪款最好」、分段汇总总榜回答「各价位优等生凑一起」。

**事实榜融合核查（本次确认）**：现行产物无独立事实榜，kWh/万元、电耗已并入打分主榜作不计分参考列；
旧的全价位事实榜 HTML 是融合前历史中间产物，非现行口径。

**分段榜必须配三段评价**（`build_price_band_report.py`）：① 各段选车逻辑（入门选配置密度 / 主流选能力上限 /
高端选级别之外的服务与质感）；② 段内对比逻辑（同预算段比才公平，段内名次比总榜名次更有意义）；
③ 低价位段能否超越高价位段——用「剥离性价比后的 7 维归一化产品力分」实证：2026-10 中型纯电 SUV
入门段均值 80.1 > 主流段 79.4 > 高端段 79.0，全池产品力第 1 是 15.98 万 MONA L05（86.8）。
边界如实披露：高端段仅 1 款、主观质感项未纳入打分，产品力分只回答可量化维度，不等于「能买到且值得买」。
**铁律：全价位总榜与各段榜单都是 8 维全方面对比，性价比（11.7%）必须计入、不可剥离；
产品力口径绝不混进主榜、不改主榜名次。**

## v8.3.3 · 纯产品力总榜：双榜并存（2026-11-19）

用户要求「再增加一个剔除性价比的总榜，剔除价位影响单纯对比产品力」。这不是推翻 v8.3.2 铁律——
铁律针对**主榜**（不可剥离）；这里额外并列一张明确命名的辅助榜。

- `board_v2.py` 的 `product_power_board()`：剔除性价比（value 11.7%）→ 其余 7 维按原权重归一化 ×10
  → **全池混排、不分价位段**（目的正是跨价位比产品力）。`build()` 输出 `product_power_board` 字段。
- `rank_delta = 主榜名次 − 产品力名次`：正=剔除性价比后名次上升（性价比拖累），负=靠性价比抬升。
- **纪律**：这是并列【辅助榜】，主榜（8维含性价比）仍是唯一权威排序，本榜不改主榜任何名次/分数/权重；
  两榜分开标注。维度不全的车不进产品力榜。
- 21 款实测：MONA L05 主榜#4→产品力#1（↑3）、小鹏G6 #11→#17（↓6，最靠性价比抬升）、
  宋Ultra EV #14→#8（↑6，价格缺失未归类但仍在全池榜）。selftest 增至 7 项全过。

## 已知边界（SKILL.md 有完整版）
- 候选池主体仍需人工维护，自动发现只覆盖「已报备未上市」层（filings.py）
- C-NCAP 官网首页 swiper SSR 可自动抓最新批次（`fetch_cncap.py`），历史批次仍需人工汇总；C-IASI 有公开 GET 全量成绩表（v6.3 已接入 189 条）。但 C-IASI 等级图标无官方文字对照，**未解码**；成绩不外推年款/配置
- 第三方视频证据必须人工核验后入库（`thirdparty_tests.json`），自动抓视频不可靠
- 气囊配置按 trim 人工核验，2026-10 覆盖 **25/39（64%）**；未核验的写 `null`，不参与任何加减分
- 官网配置事实覆盖 9/39，且**只记事实不改分**；3 个待准入维度因覆盖率 <70% 整条禁用
- 逐配置阶梯覆盖 **35/39（89.7%）**（4 款人工核验 + 31 款参数页自动解析），
  只列事实与场景分支、不加分；自动条目按「能源类型」列只留纯电动款型，190 个款型零残留。
  剩 4 款查无车系、4 款 `trim.price` 与官方指导价冲突，均只披露不擅改
- **四榜与月度安全分口径已统一**（v6.1 `blend`，α=0.5），四榜 safety sd 现算
  0.235 / 0.289 / 0.210 / 0.414；跨产物比较安全分有效，但分数有区分度 ≠ 有官方碰撞证据
- 非阻断步骤（乘联会大盘 / 备案导出 / 投诉抓取）失败会缺分区，以 `run.log` 的 ✗ 为准
- **统一榜是唯一口径**：没有独立事实榜，kWh/万元/电耗等只作不计分参考列；跨批评分尺度差异不强行拉平
  （拉平会制造假精度），相邻名次的分差不能当精确结论
- **总池 67 款**是单一事实源，但池外新车需走 `--intake` / 人工采集；`--audit` 可查覆盖缺口
- **多源核验冲突如实披露**：价格/销量的口径差（配置价 vs 车系价、中位 vs 当期）保留 CONFLICT 并在
  cause 写明，不强行裁决；网查确认只写 ≥2 个独立权威源一致的值
