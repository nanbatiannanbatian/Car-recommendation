# Car recommendation

> 可信购车榜单引擎：口径闸门 / MCDA 稳健性检验 / 工信部备案预测 / 证据分层 / 历史回测。
> 无模型调用，同一输入必得同一输出。

## 这是什么
WorkBuddy 用户级 skill。核心是「车型排行榜全链路」：取数→闸门→打分→稳健性→三档→审查→报告，
外加 工信部备案抓取/上榜预测/第三方视频证据/被动安全配置核验/数据仓库回测。**榜单链路全程无模型调用**，
同一输入必得同一输出。原多模型辩论引擎已于 2026-11 移除——为什么不用 LLM 直接排名，见 SKILL.md《为什么出榜流程不含 LLM/辩论》。

## 安装
把本文件夹复制到 `~/.workbuddy/skills/` 下（安装身份沿用 omni-debate），重启会话即可被识别。

## 依赖（别人怎么装）
Python 3.10+。依赖没有打包进 zip，是标准的 Python 包管理方式：

    pip install -r requirements.txt          # 必需：requests、olefile

可选功能各自由依赖开关，**缺了不阻断出榜**，只少对应步骤并在 run.log 写明：

    pip install akshare                      # 乘联会大盘校验（装不上加阿里云镜像）
    npm install -g opencli                   # 汽车之家级别/价格对齐（fetch_specs.py）

最小说明：只装 requests + olefile，`pipeline.py`（闸门→打分→三档→审查→报告）
和 `forecast.py`/`warehouse.py` 全部可用；akshare 只影响大盘快照，opencli 只影响对齐一步。

**什么都不用配。** 榜单链路无模型调用、无 API key、无密钥文件。

## 里面对电动车榜硬编码的东西（换品类要改）
- `categories/car_ev.json`：纯电中型/中大型四榜的口径配置
- `categories/baseline_car_ev.json`：人工维护的候选池
- `categories/airbags.json`：按带内推荐配置核验的气囊三态库（true / false / null=未核验），每条带可点开的 url + 核验日期
- `categories/trims.json`：按具体配置记录的指导价 / 电池容量 / 电芯供应商 / 技术路线 / 上市时长，每条带 url + quote + 核验日期
- 换咖啡机等其它品类参考 `categories/coffee_grinder.json` 的结构，代码不用改

## 被动安全配置为什么不进主分（v5.8）
侧气囊、头部气帘、前排中央（远端）气囊确实重要（NHTSA：侧气帘＋躯干气囊让近侧碰撞死亡率降约 30%）；
但 C-NCAP 2024 版乘员保护已含侧碰、柱碰、侧面远端乘员保护 8 分、保压气帘 3 分——
**气囊是拿分手段，得分率是结果**，再按配置加分等于重复计入。所以本项目：

- 报告出「气囊 侧/帘/中」**事实列**，不计入加权；
- 只对**无官方碰撞成绩**的车给 `scores.safety` 一个受限增量（|Δ| ≤ 0.3，标 low confidence，逐条可撤销）；
- 有成绩的车一律不叠加；「N 气囊」营销口径不映射到布尔字段；
- 未核验的写 `null`，不判劣、不造差异，`airbags.py --todo` 列待补清单。

详见 SKILL.md《被动安全气囊：事实列与受限修正（v5.8 · 方案 A）》及 `airbags.json` 里的 A1–A7 规则。

## 细分维度为什么不进主分（v5.9）

有人提过把轮胎品牌、制动距离、维修经济性、售后态度、保养经济性、底盘用料、试驾感受、
麋鹿成绩、防爆胎、电耗、空间、NVH、智驾、主动安全、流畅度、马力等十几项做成
「成绩好就加一点分，没数据或不确定不加分」。**本项目不做**，理由不是保守，是五个具体失效模式：

1. **缺数据不是随机的（MNAR）**：高曝光、营销预算足的车型披露的参数与实测远多于冷门车型，
   「有数据就加分」实际在给曝光度打分。
2. **选择性披露**：厂商只公布最优条件下好看的数字，缺的往往是不好看的；只加不减会系统性奖励会宣传的品牌。
3. **双重计数**：马力/电耗已在 `powertrain`，空间在 `space`，智驾/主动安全在 `adas+safety`，
   流畅度在 `cabin`，制动/麋鹿在 `control`——再加一次是同一份表现付两次分。
4. **稀疏噪声劫持权重**：覆盖率 10–30% 的维度，方差几乎全由「有没有数据」决定；
   十几个这样的维度叠加，MCDA 会被"谁被报道得多"主导。
5. **不可归一化**：100-0 制动跨媒体的胎温/载重/路面/初速不同；麋鹿只有少数媒体测；
   试驾、售后、NVH、流畅度是主观或口碑口径，样本小且立场不同。

替代方案写成了可执行的 `spec_facts.py` + `categories/spec_facts.json`：

- **16 项决策表**，分六类处置：已吸收·不加分（6）、封顶通道·双向（2）、仅事实列（4）、
  用户偏好滑杆（1）、不采集（2）、有官方口径·待准入（1，中保研 C-IASI 维修经济性指数）。
- **维度级准入门槛 G1–G4**：官方标准化口径 + 覆盖率 ≥70% + 可核验来源 + 加减双向对称。
  不达标就**整条维度禁用**，而不是把缺失记 0 分。本期 3 个待准入维度覆盖率都是 0%，全部禁用。
- **红线 `SCORING_ENABLED=False`**：`apply()` 只写 `c['spec_facts']`，并在返回前对
  `scores/total/adjust` 做前后深比较断言——事实库在代码层面不可能改排名。
- 官网/逐项参数配置照收（按 trim、带 url + quote + 日期），只进事实列与待补清单。

主观项（NVH、试驾）不做成默认权重，交给读者用 `--sliders` 自己拉。

## 安全分对齐（v5.9）

月度链路此前漏了 `sync_cncap.py`，安全分一直是人工值。现已接入并按
`--fill-mode blend`（α=0.5，人工分与中位各半）处理无成绩车：

| 模式 | 中型车 sd | 中型SUV sd | 中大型车 sd | 中大型SUV sd | 说明 |
|---|---|---|---|---|---|
| 原人工分 | 0.348 | 0.379 | 0.368 | 0.442 | 无证据支撑，但保留区分度 |
| `median` | 0.077 | 0.260 | 0.070 | 0.112 | 旧行为：31 款落到同一数，18% 权重失效 |
| `blend`（默认） | 0.208 | 0.276 | 0.210 | 0.414 | 官方成绩覆盖 + 保留相对序，全部标 low |
| `manual` | 0.359 | 0.305 | 0.462 | 0.736 | 只覆盖有成绩车，其余保留人工分 |

三种模式都可回退对照，α 可调。C-NCAP 官网首页最新批次可自动解析，
历史批次仍需人工汇总；C-IASI 全量成绩表已于 v6.3 接入（见下节）。

## 具体配置推荐：为什么列、为什么不加分（v6.0）

榜单只按一个「带内推荐配置」打分，容易掩盖买车时真正要做的选择：
**同一车系不同配置的电池容量、电芯供应商、电压平台可能完全不同。**
例如 MG 07 的 610/650 版是苏州清陶 67kWh 半固态 + 400V/3C，
845 版是宁德时代 91kWh 三元锂 + 800V/5C；腾势 N8 加 1 万多 24.36kWh。

**结论：该列，而且这是很值得补的一层；但不该把它变成加分项。**

1. **层级错位**：榜单回答「买哪款车」，配置推荐回答「这款车买哪个版本」。写进加权分等于用配置性价比替代整车评价。
2. **配置性价比是场景函数**：同一笔 +1 万换大电池，有无家充、南方北方、通勤长途结论相反。
   腾势 N8 这一笔被一篇媒体称「六款中单位成本最划算」，另一篇明确写「只为续航加 1 万没必要」——
   没有唯一正确答案就不能进默认权重。
3. **MNAR 同样存在**：放出逐配置表的是高曝光车型，缺表就吃亏等于给披露完整度打分。
4. **「低配二线电池、高配宁德」的概括不成立**：零跑 C10 逐配置表写的是
   「国轩高科/亿纬动力/中创新航」**同配置多供应商混装**，选配置也规避不了；
   MG 07 是**技术路线分层**（半固态 vs 三元锂 + 400V vs 800V），不是供应商等级。
   电池包由整车厂集成，公开数据不足以按电芯品牌拆分长期可靠性——
   所以本项目**不给供应商排一线/二线/三线，也不映射任何分数**，
   只分类证据形状、只记「是谁、什么路线、上市多久」。

落成 `trims.py` + `categories/trims.json`：

- 按 trim 记录指导价 / 电池容量 / 电芯供应商 / CLTC / 补能 / 电机 / 上市时长，每条带 url + quote + 日期；
- 识别「加价-增配跃迁」：同年款内、每万元 ≥10kWh 或 ≥100km、目标须在价格带内；
  超过 1.5 万加价阈值判 `platform_step`（换整条三电路线），**只陈述事实与场景分支，不给单一建议配置**；
- 建议只从「评分配置」出发，其它支线的加价差异只进事实表；主观取舍按场景分支交还读者；
- 「评分配置」保持候选池原值，不替换、不改 `price_basis`、不动闸门；
- 带外车型（如腾势 N8，26.99–32.99 万）只作算法演示，绝不参与四榜名次。

**红线**：`SCORING_ENABLED=False`，`apply()` 只写 `c['trim_ladder']`，返回前对
`scores/total/adjust/price/trim` 做深比较断言。主报告出精简节，
逐配置表、带外示例与来源链接出 `out/trims.md`；`--no-trims` 可作回测对照。
本期 2026-10 首版核验 4/39 款；**v6.1 已补到 35/39**，见下节。

## v6.2 · 按外部评审做的披露强化（基准名次零变化）

外部评审指出公式不透明、插补比例高、销量权重偏重、0.1 分假精确、分动力榜不足 10 款
却写「前十」等问题。核对后 6 条成立、2 条读错（分动力视图其实**用同一套加权分**，
只是参照系换成同动力子集；此前只给同档组号、没给逐车名次区间）。

落地全是披露层、不改分数与名次：正文补「权重 / 公式 / 归一化 / 覆盖率」复现节；
表格加 **bootstrap 名次区间(95%)** 并注明 0.1 分不可辨；分动力标题改为
「分列（共 N 款）」，N<10 明说尾部无统计意义；明确本榜是
「市场热度 / 指导价 / L4 口碑综合参考」。顺带修掉一个真 bug：
配置 `gap` 写「权重上限 22%」而实配 **24%**，旧报告照抄了 22%，现按实配值披露。

新增 `ice_sensitivity.py` 三情景压力测试（基准 / 去掉销量维 / 禁用插补维）。
**结果**：去掉 market 维后全榜 Kendall τ 掉到 **0.238–0.446**、前十只剩 **4–6/10**，
说明销量才是主要驱动；禁用插补维后前十仍留 **8–9/10** 但 τ 仅 **0.667–0.779**，
说明插补对头部影响有限、对整体排序影响显著。
四榜前十与 v6.1 **完全一致**。

- 逐配置阶梯覆盖 **35/39（89.7%）**（4 款人工核验 + 31 款参数页自动解析），
  只列事实与场景分支、不加分；自动条目按「能源类型」列只留纯电动款型，190 个款型零残留。
  剩 4 款查无车系、4 款 `trim.price` 与官方指导价冲突，均只披露不擅改
- **四榜与月度安全分口径已统一**（v6.1 `blend`，α=0.5），四榜 safety sd 现算
  0.235 / 0.289 / 0.210 / 0.414；跨产物比较安全分有效，但分数有区分度 ≠ 有官方碰撞证据
- 非阻断步骤（乘联会大盘 / 备案导出 / 投诉抓取）失败会缺分区，以 `run.log` 的 ✗ 为准
